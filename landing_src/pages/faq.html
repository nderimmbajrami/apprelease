FAQ

Questions and answers.

Did not find yours? Write to us, we answer within a business day.

Building

Do I need a Mac for the iOS build?

No. iOS builds run on AppRelease's macOS runners with a current Xcode. On the Scale plan you can register your own Mac as a runner.

Which Flutter versions are available?

Any stable, beta or master build, or a specific version like 3.41.2. FVM projects are detected and respected. See setting the Flutter version.

Can I run tests before the release?

Yes. Add a script step with flutter test before the build step. If it fails, nothing is uploaded. AppRelease is not a test runner with device farms, though; for that keep your CI and let AppRelease do the publishing.

How long does a release take?

A typical Flutter app takes three to five minutes for Android and five to eight for iOS, mostly spent in the Flutter build itself. Dependencies and the Flutter SDK are cached between runs.

Signing and secrets

Where are my keys stored?

Encrypted at rest. A runner decrypts them into a temporary directory for the duration of one build and removes them when the build ends, whether it passed or failed. Nobody at AppRelease can read them.

Can I download the keystore I uploaded?

No, on purpose. Keep your own copy somewhere safe: every future Google Play release has to be signed with the same key.

Do you support automatic iOS signing?

Yes. With an App Store Connect API key, AppRelease creates or fetches the distribution certificate and provisioning profile for the bundle identifier. You can also upload your own certificate and profile instead.

Publishing

Can AppRelease publish a brand-new app?

Partly. The store listing (name, screenshots, description) has to be created once in Google Play Console or App Store Connect, and the very first Google Play upload has to be done by hand. After that, every release goes through AppRelease. Use submit_as_draft: true while the app is still in draft on Google Play.

Which Google Play tracks are supported?

Internal, alpha, beta, production and custom tracks, with optional staged rollout percentage.

Does it submit to App Store review?

It can. submit_to_app_store: true creates the App Store version, attaches the build and submits it for review. Most teams stop at TestFlight and submit by hand; both work.

General

Is this only for Flutter?

Today, yes. The workflows are plain shell scripts, so a React Native or native project builds fine already; what is missing is the guided setup and the quick start. React Native is next.

I already use another CI. Is moving painful?

No. apprelease.yaml is one short file: workflows, environment, scripts, artifacts, publishing. Most existing pipelines translate in a few minutes, and the console generates a starting point from your app settings.

Where does AppRelease run?

The control plane runs in the EU. macOS runners are Apple Silicon machines; Linux runners are used for Android when no iOS build is needed.

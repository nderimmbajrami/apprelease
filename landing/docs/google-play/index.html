    Google Play publishing

    AppRelease uploads the app bundle to a Google Play track with a service account you create once in Google Cloud.

    Requirements

    • The app exists in Google Play Console and the first bundle was uploaded by hand. Google requires that; every bundle after it can go through AppRelease.
    • The bundle is signed with the upload key (see Android code signing).

    Creating a service account

    1. In the Google Cloud Console, choose or create a project and open IAM & Admin → Service accounts.
    2. Click Create service account, name it (for example "apprelease-publisher") and finish without granting project roles.
    3. Open the account, go to Keys → Add key → Create new key → JSON. The file downloads once.
    4. In Google Play Console, open Users and permissions → Invite new users, enter the service account's email address and grant it Release to production, exclude devices, and use Play App Signing and Release apps to testing tracks for the app. Admin is not needed.
    It can take a few minutes, sometimes longer, before Google Play accepts calls from a freshly invited account. A "The current user has insufficient permissions" error on the first release is usually just that.

    Storing the key in AppRelease

    1. Open the app in the console → Environment variables.
    2. Variable name GOOGLE_PLAY_SERVICE_ACCOUNT, value: the entire contents of the JSON file.
    3. Group name google_play. Click to create the group.
    4. Make sure Secret is checked, then Add.

    Configuration

    workflows:
  android-workflow:
    environment:
      groups:
        - google_play
    publishing:
      google_play:
        credentials: $GOOGLE_PLAY_SERVICE_ACCOUNT
        track: internal            # internal | alpha | beta | production | a custom track
        submit_as_draft: false     # true while the app is still in draft
        rollout_fraction: 0.1      # optional staged rollout on production
        in_app_update_priority: 0  # optional, 0–5
        changes_not_sent_for_review: false
    KeyDefaultDescription
    credentials—The service account JSON, by variable reference.
    trackinternalWhere the release lands.
    submit_as_draftfalseRequired while the app has never been published.
    rollout_fraction—Staged rollout, 0.01–0.99. Omit for 100 %.
    in_app_update_priority0Priority shown to the in-app updates API.
    changes_not_sent_for_reviewfalseUpload without sending the change for review.

    Release notes

    Put a release_notes.txt, or release_notes_en-US.txt and friends, in the repository root. They are attached to the track release in the matching languages.

    Common errors

    MessageUsually means
    Version code 57 has already been usedUse versioning: source: google_play so the build number comes from the store.
    Only releases with status draft may be created on draft appAdd submit_as_draft: true.
    The Android App Bundle was signed with the wrong keyThe keystore is not the upload key. See checking the signature.
